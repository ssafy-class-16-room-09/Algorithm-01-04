# 🏆 삼성 SW 역량테스트 B형 대비 알고리즘 스터디

> 자료구조를 **직접 구현**하고, 시간복잡도를 **스스로 개선**하는 훈련으로 B형(Professional)을 뚫는 스터디

## 📌 스터디 소개

- **목표**: 삼성 SW 역량테스트 B형 취득
- **기간**: 13주 커리큘럼 + 시험 전까지 실전 연장
- **인원**: 4명 (SSAFY 수강생)
- **진행 방식**
  - 주중: 개념 학습 → 노션에 정리글 업로드 → 과제 코드 PR 제출
  - **매주 목요일 수업 후**: 오프라인 2시간 (실전 풀이 75~90분 + 풀이 공유 30분)
  - Phase 4부터 격주 주말: 4시간 풀타임 모의

### B형이란?

- 4시간 동안 1문제, **구현 + 최적화** 중심 출제
- Main은 제공되고 **Solution 함수만 구현**하는 형식
- 라이브러리(STL 등) 사용 가능하지만, 자료구조 설계 능력이 그대로 드러나는 시험
- 백준 기준 골드4 ~ 플래티넘 수준의 최적화 문제

## 📏 스터디 규칙

| # | 규칙 |
|---|---|
| 1 | **Phase 1에서는 `java.util` 컬렉션 금지** — 연결 리스트, 해시, 힙은 배열과 직접 만든 클래스로 짠다 (Phase 2부터 해제) |
| 2 | **깃허브에는 최종 코드만** — 각자 개인 브랜치에 push. 풀이 과정·중간 시도는 노션 「풀이 기록」에 |
| 3 | **못 풀어도 기록** — 접근 과정과 막힌 지점을 노션 풀이 기록에 남긴다 (결과: 접근만/미해결) |
| 4 | 풀이 공유는 정답 자랑이 아니라 **"어떤 자료구조를 왜 골랐고, 복잡도를 어떻게 줄였는가"** 중심 |
| 5 | 3주차 · 8주차에 페이스 회고 — 버거우면 커리큘럼 조정 |

## 🗓 커리큘럼

### Phase 1 — 자료구조 구현 부트캠프 (1~3주)

| 주차 | 개념 | 구현 과제 | 응용 문제 |
|---|---|---|---|
| 1 | 연결 리스트, 스택/큐 | 연결 리스트 클래스 (insert/delete/find) + 테스트케이스 | SWEA 1225 암호생성기, PGS 주식가격 |
| 2 | 정렬(퀵/머지), 이진 탐색 | 퀵소트·머지소트 직접 구현 + `sort()` 대조 검증 | PGS 가장 큰 수, PGS 입국심사 |
| 3 | 해시, 힙 | 체이닝 해시 테이블 (put/get/remove) | PGS 전화번호 목록(또는 베스트앨범), PGS 더 맵게(힙 직접 구현) |

### Phase 2 — 핵심 알고리즘 (4~8주) ★ 승부처

| 주차 | 개념 | 과제 |
|---|---|---|
| 4 | DFS / BFS | PGS 타겟 넘버, 게임 맵 최단거리 → 네트워크 or 단어 변환 |
| 5 | DP ① 메모이제이션 | 피보나치 3-way 구현(재귀/메모/반복) + 시간 비교, PGS 정수 삼각형, 등굣길 |
| 6 | DP ② 배낭 + 그리디 | 0/1 배낭 직접 구현(코드 리뷰 검증), PGS 구명보트, 단속카메라 |
| 7 | 비트마스킹 | 비트 연산 치트시트 정리, SWEA 부분집합의 합, PGS 후보키 |
| 8 | 다익스트라 + 우선순위 큐 | PGS 배달 → 합승 택시 요금, 스케줄링 유형 1문제 |

### Phase 3 — 심화 (9~11주)

| 주차 | 개념 | 과제 |
|---|---|---|
| 9 | 트리 구현(자식 수 미정) + LCA 개념 | 트리 구현(순회/깊이 포함), PGS 길 찾기 게임 |
| 10 | Trie + 문자열 | Trie 직접 구현 (insert/search/startsWith), PGS 가사 검색 |
| 11 | 세그먼트 트리 + 버킷 | 구간 합 세그트리 구현 + 브루트포스 대조 검증 |

### Phase 4 — 실전 (12주~)

- 주중: SWEA **SSAFY Pro 연습** 기출 1문제/주
- 오프라인: 기출 1문제 90분 실전 모드
- **격주 주말: 4시간 1문제 풀타임 모의** (실제 B형 형식)

## 📂 저장소 구조

각자 **본인 이름의 개인 브랜치**에서 작업하며, 브랜치 안 구조는 아래를 따른다. **최종 코드만** 올린다 (중간 시도·실패 코드는 노션 풀이 기록에).

**폴더 구조 예시**
```
(브랜치: 홍길동)
.
├── README.md
├── week01/
|   ├── online/
│   │   ├── MyLinkedList.java  
│   │   ├── Swea1225.java
│   │   └── PgsStockPrice.java
│   └── offline/       
│       ├── Problem01.java
│       └── Problem01.java
├── week02/
|   ├── online/
│   └── offline/ 
```

**Java 규칙**
- 파일명은 영문 PascalCase (파일명 = public 클래스명). 어떤 문제인지는 클래스 상단 주석 한 줄로
- `package` 선언 없이 올린다 (레포는 아카이브용, 실행은 각자 로컬 프로젝트에서)
- Phase 4부터는 실전처럼 `Solution` 클래스 형식으로 작성 연습

## 🔀 제출 방법

1. 본인 이름 브랜치 생성 (최초 1회): `git checkout -b `
2. 해당 주차 폴더에 **최종 코드만** 커밋
3. **수요일까지** push + 노션 「풀이 기록」에 문제별 페이지 작성
   - 풀이 기록에는 최종 코드의 깃허브 링크를 걸어서 연결
   - 못 푼 문제는 코드 없이 풀이 기록만 작성해도 됨 (결과: 접근만/미해결)
4. 커밋 메시지 형식 : `[주차] 문제` (예시 : `[01] SWEA 1225`)

## ✍️ 풀이 기록 규칙

**풀이 과정·고민·실패한 시도는 전부 노션 「풀이 기록」 DB에** 남긴다. 


실패한 시도를 기록하는 핵심!! 
B형은 "느린 풀이 → 빠른 풀이로 개선"하는 시험이니, 실패 접근의 복잡도를 계산해본 기록 자체가 훈련이다!
